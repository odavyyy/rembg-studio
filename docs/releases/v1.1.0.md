# Rembg Studio 1.1.0

**[Leia em português](#em-português)** · English below

Adds in-app updates, an About page and clearer privacy and licensing documents. **The interface is in Brazilian Portuguese.** You need rembg installed; no model is included. See the README.

## Downloads

| File | What it is |
|---|---|
| `RembgStudio-Setup-1.1.0.exe` | Installer, per user. **Not tested.** |
| `RembgStudio-1.1.0-portatil.exe` | Single portable file. **This file has not been tested.** |
| `RembgStudio-1.1.0-win-x64.zip` | Extract and run `Rembg Studio.exe`. **This file was tested** (see Testing). |
| `RembgStudio-1.1.0-Source.zip` | Source code of the tagged commit. |
| `SHA256SUMS.txt` | Checksums for the files above. |

The builds are **not code-signed**; Windows SmartScreen may warn you.

## Changes

- Manual update check, download with progress and cancel, SHA-256 verification, confirmation before installing.
- About page with documents and support links.
- One-time notice for `bria-rmbg`: **non-commercial use only**; commercial use needs an agreement with BRIA.
- ONNX Runtime telemetry is disabled for the app's rembg process.
- `elevate.exe` is no longer included.

Coming from 1.0.0: download this version by hand; 1.0.0 has no updater.

## Testing

One machine: Windows 11 Pro, RTX 5060 Ti.

Of the packages built by GitHub and attached here, **only `RembgStudio-1.1.0-win-x64.zip` was tested**. Its SHA-256 matched the one shown by GitHub, its 79 files were byte-identical to a local build of the same commit, and the 33 app checks passed on it with the real rembg installation and GPU (Windows dialogs and drag and drop were simulated). While processing with an already downloaded model, no external connection was observed; with an update check, only the GitHub request appeared.

**The installer and the portable `.exe` attached here have not been run or tested.**

The 39 updater checks ran on local builds made before the final commit, which changed only documentation, ownership and workflow comments. In them, the portable version-to-version update was real, with a locally served test release and a stubbed confirmation; server failures were simulated. Not tested: the installer, updating from a real published release, signed builds.
